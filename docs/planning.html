Take-home tasks that don't need the robot (all tracks)

  • Sim: python -m robotpy sim (no robot, pure sim with the GUI: drive with a gamepad, test commands, Field2d). Plus the sim --xrp dry run (runs and connects when a robot is nearby).
  • Calibration math: wheel-diameter correction, counts→meters, the track-width-from-spin-test formula, σ(d) fitting from logged CSVs (spreadsheet or Python).
  • Vision offline: run robotpy_apriltag on photos taken at the meeting or with a phone of printed tags (pose from known size); calibrate from checkerboard images in OpenCV.
  • Code review: GitHub PRs between groups; one reviewer per PR.
  • Reading: WPILib docs on pose estimators, LTVUnicycleController, commands2, AprilTag; PhotonVision docs; the XRP user guide.
  • Docs: each group writes a one-page "how it works" for its piece.

Fallback rule

  • Each track's gates are listed in its table. If 2 gates are missed (cumulative, not necessarily consecutive), drop to the next track (Aggressive → Balanced → Relaxed). At the drop, re-plan the remaining weeks using that track's table from the current week on.
  • A gate is missed if its success criteria (roadmap numbers) aren't met by the end of the gate's meeting. One catch-up week is allowed, but if it's still unmet it counts as missed (ASSUMPTION: grace period).
  • Moving up a track is allowed only if all gates so far were met a week early.

Track-agnostic risks

  • The meeting day is unknown. Tables use weeks, so confirm the day and adjust (Saturday meetings lose Jan 9 to Kickoff).
  • Single V1 and single Pi: hardware can only be at one home at a time. Rotate a check-out schedule.
  • School laptop install restrictions; Wi-Fi AP client limits (about 4, UNVERIFIED).
  • Battery supply (NiMH sets) and power-bank availability.
  • Season-registration admin (Nov 17) and the Virtual Kit (Nov 12) are mentor tasks, not kid tasks.
